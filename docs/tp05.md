# План тестирования

## 1. Стратегия тестирования

### 1.1. Общий подход
Тестирование YT Pulse проводится с акцентом на **интеграционное тестирование потоков данных** (YouTube API → кэш → разбор превью → UI) и **оценку качества локального разбора превью**, так как это критические компоненты системы.

### 1.2. Уровни тестирования
- **🔧 Модульное тестирование**: Парсинг ответа YouTube API, нарезка фильтров, алгоритмы OpenCV/MediaPipe
- **🔄 Интеграционное тестирование**: Связка Next.js API ↔ Neon, API ↔ YouTube Data API, API ↔ ЮKassa Test
- **🎯 Системное тестирование**: Полный цикл от входа до генерации превью
- **👥 Приемочное тестирование**: Соответствие UI макетам ТЗ, удобство на разных устройствах

## 2. Объекты тестирования

### 2.1. Ключевые модули для тестирования

#### **📈 Трендовый пайплайн**
- Корректность запроса к YouTube Data API (`mostPopular`, region=US)
- Применение 6 фильтров на сервере (All, Shorts, Longform, Gaming, AI, Finance)
- Сохранение и чтение кэша из Neon PostgreSQL
- Кнопка "Обновить кэш" корректно перезаписывает данные

#### **🔍 Разбор превью (Why it clicks)**
- Скачивание JPG с `i.ytimg.com` (все 3 fallback-разрешения)
- MediaPipe Face Detection: корректность определения площади лица
- OpenCV: корректность расчёта контраста (σ), текстовой зоны, центра объекта
- Таблица `preview_tags` содержит корректные `score_sum` (0–4)
- Сортировка списка по убыванию `score_sum` (стабильная)

#### **🎨 Генерация (Pro)**
- Проверка плана Pro перед доступом к экрану
- Интеграция с Groq/Gemini (текст) — ретраи, fallback, таймауты
- Интеграция с Pollinations/Gemini Flash (изображение) — 3 варианта 16:9
- Статусы шагов на форме: текст → картинка → готово

#### **💳 Оплата**
- Создание платежа в ЮKassa Test
- Корректность webhook (сырой payload сохраняется в `payments`)
- Обновление `users.plan = pro` и `pro_expires_at` после успеха
- Экраны успеха и ошибки отображаются корректно
- Free-пользователь не может попасть в генерацию (замок + редирект)

## 3. Методы тестирования

### 3.1. Функциональное тестирование

#### **Тест-кейсы трендового пайплайна**
```python
Test Case: "Обновление кэша и фильтрация"
- Действие: Нажать "Обновить кэш"
- Ожидаемый результат:
  ✓ Запрос к YouTube API выполнен (region=US, mostPopular)
  ✓ Данные сохранены в trends_cache
  ✓ Фильтр Shorts показывает только ролики ≤ 60 секунд
  ✓ Фильтр AI показывает ролики из Science & Technology с ключевыми словами
```

#### **Тест-кейсы разбора превью**
```python
Test Case: "Локальный разбор JPG"
- Предусловие: Кэш трендов обновлён
- Действие: Открыть экран "Превью", выбрать фильтр All
- Ожидаемый результат:
  ✓ Для каждого нового video_id скачан JPG
  ✓ MediaPipe определил лицо (если оно есть и ≥ 12%)
  ✓ OpenCV рассчитал контраст (σ ≥ 55 → high_contrast=true)
  ✓ Список отсортирован по score_sum по убыванию
  ✓ Справа отображаются ровно 3 тега (без процентов, без center_object)
```

#### **Тест-кейсы оплаты**
```python
Test Case: "Тестовая покупка Pro на 1 месяц"
- Действие: Выбрать Pro месяц → оплатить через ЮKassa Test
- Ожидаемый результат:
  ✓ Виджет отображает бейдж TEST MODE
  ✓ Деньги не списываются с реальной карты
  ✓ Webhook получен и сохранён в payments.raw_webhook
  ✓ users.plan = 'pro', pro_expires_at = now + 1 месяц
  ✓ Открывается экран успеха с CTA в генерацию
```

### 3.2. Интеграционное тестирование

#### **Сценарии взаимодействия**
1. **Полный цикл Free-пользователя**
   ```
   Регистрация -> Вход -> Лента трендов (All) -> Выбор ролика ->
   Разбор превью (3 тега) -> Попытка генерации -> Замок -> Тарифы
   ```

2. **Полный цикл Pro-пользователя**
   ```
   Оплата Pro -> Лента -> Выбор тренда -> Генерация превью (3 варианта) ->
   Очередь ролика -> Статусы queued → rendering → ready -> Плеер-заглушка
   ```

3. **Мультипользовательский режим**
   ```
   User A (Free) открывает ленту -> User B (Pro) генерирует превью ->
   Оба видят корректные данные и границы своих тарифов
   ```

### 3.3. Тестирование UI/UX

#### **Кроссдевайс тестирование**
- Отображение кабинета на десктопе (основной таргет)
- Корректная работа на мобильных устройствах (адаптивность Tailwind)
- Работа в Chrome, Safari, Firefox

#### **Соответствие макетам**
- Тёмная тема: фон #07080C, поверхность #12141C, линия #262B3A
- Акцент #FF3B4E, Pro #8B6CFF
- Сайдбар 228 px, рельс 320 px, нижний бар 72 px
- Превью строго 16:9, object-fit: cover

## 4. Критерии успеха тестирования

### 4.1. Критерии прохождения тестов

#### **Функциональные критерии**
- ✅ Регистрация и вход работают корректно
- ✅ Лента US загружается, 6 фильтров применяются без `search.list`
- ✅ Разбор превью считает 3 тега локально, сортировка корректна
- ✅ Free не пускает в генерацию (замок + редирект на тарифы)
- ✅ Тестовая оплата ставит Pro на выбранный срок
- ✅ Pro генерирует 3 варианта превью
- ✅ Задача ролика создаётся со статусами queued → rendering → ready

#### **Производительностные критерии**
- ✅ Обновление кэша < 10 секунд
- ✅ Генерация пака превью < 30 секунд
- ✅ UI не блокируется во время загрузки или генерации
- ✅ Первый токен от AI < 3 секунд

#### **Критерии удобства использования**
- ✅ Интерфейс соответствует макетам ТЗ (единый каркас)
- ✅ Понятное разделение Free / Pro функций
- ✅ Корректное отображение превью 16:9

### 4.2. Критерии завершения тестирования

- **Прохождение 95%+ тест-кейсов**
- **Отсутствие критических багов** (ошибки оплаты, падение разбора превью, утечка секретов)
- **Соответствие UI макетам** ТЗ как источнику правды
- **Все 10 критериев готовности из ТЗ выполнены**

## 5. Инструменты тестирования

### 5.1. Автоматизированное тестирование
- **Jest + React Testing Library** — модульное тестирование UI-компонентов
- **Playwright** — E2E тестирование (вход, лента, оплата)
- **pytest** — тестирование алгоритмов OpenCV/MediaPipe (если вынесены в Python-микросервис)
- **httpx / fetch** — тестирование API-эндпоинтов

### 5.2. Ручное тестирование
- **Проверка макетов** — сравнение UI с описанием ТЗ (цвета, размеры, отступы)
- **Тестирование на разных устройствах** (ПК, планшет, телефон)
- **Валидация промптов** — оценка качества генерации превью
- **Проверка ЮKassa Test** — тестовые карты, проверка отсутствия реальных списаний

## 6. Результаты тестирования

### 6.1. Статус тестирования
- **Модульное тестирование**: ⏳ В процессе
- **Интеграционное тестирование**: ⏳ В процессе
- **Системное тестирование**: ⏳ В процессе
- **Приемочное тестирование**: ⏳ В процессе

### 6.2. Ключевые зоны риска
- **Vercel Hobby limits**: Время выполнения serverless function может не хватить для разбора большого пакета превью — требуется порционная обработка
- **MediaPipe + OpenCV в serverless**: Возможны сложности с установкой нативных зависимостей на Vercel — может потребоваться внешний микросервис или Docker
- **AI-провайдеры**: Лимиты бесплатных API (Groq, Pollinations) могут исчерпаться — критично проверить fallback-логику
- **YouTube API квоты**: `mostPopular` жрёт квоту — важно не обновлять кэш чаще необходимого
